# 発想A 13案の評価

## A1. AI答弁公文書館（LLM Answer Archive）— スコア 6.5/10
1. **最初の1,000人の経路**: 描ける。(1)アーカイブを自力生成（ユーザー不要でデータが完成する＝コールドスタート耐性が高い）→(2)HN/GitHubでオープンデータ公開（Artificial Analysisと同じ入口）→(3)モデル廃止・挙動激変イベントのたびに「変化前後の回答本文を唯一持つ者」として記者・研究者に能動送付→(4)DOI付きデータセットで学術引用。初期トラクションの単位は「被引用」であり、Layoffs.fyi/Artificial Analysisの前例に忠実。
2. **経路の実在検証**: 強い。ソロ/2人のサイドプロジェクトが継続観測データで引用標準になった実例が英語圏に複数（Layoffs.fyi、Artificial Analysis、Aider系リーダーボード。§0-2）。「ChatGPT劣化」報道サイクルが定期発生しデータ保有者を引用する事実も確認（§0-9）。回答本文の公開恒久アーカイブの競合不在も検索で反証されず。反例: 学術系（LLMDrift等）は継続せず死んでおり、「続けること」自体が参入障壁かつ最大リスク。
3. **成長ループ内蔵度**: 半内蔵。恒久URLと被引用が次の引用を呼ぶ構造はあるが、初期の引用獲得は作者の売り込み労働。
4. **天井**: 直接訪問は月10^3〜10^4と低い（自己申告どおり）。被引用・データライセンスB2Bが本体で、「多数のユーザーに使われる」型ではない。依頼主の「ストアで見つかる・使われる」要求とはズレる点は明記しておく。
5. **維持コスト**: 週次プローブ実行はほぼ全自動化可能。API費月数万円＋質問セットの編集判断＋事件時の即応。ソロで持続可能。
6. **根拠**: 経路実在の証拠が27案中最強クラス。減点は天井の低さと、報道引用が英語圏実績に偏る点（日本語圏メディアの個人サイト引用文化は弱め）。

## A2. 求人票タイムマシン（ゾンビ求人観測所）— スコア 6/10
1. **最初の1,000人の経路**: 描ける。データは自力クロールで生成可能（UGC不要）→月次「ゾンビ求人ランキング」「掲載日数の分布」を記者・転職系YouTuber・Reddit/5ch転職スレに持ち込み→企業別恒久URLがスレッドで貼られる。最初の1,000閲覧はランキング記事1本の転載で到達可能な規模。
2. **経路の実在検証**: 中〜強。ゴーストジョブは2025年に米主要メディアの定番テーマ化し、公的統計不在のためデータ保有者（Greenhouse等）が引用され続けている（§0-2）。日本でも「おとり求人」報道は反復テーマ。反例・制約: 求人ポータルのスクレイピング規約で対象が企業直営ページ＋ハローワークに絞られると「話題の求人が載っていない」網羅性問題で共有価値が下がる。日本の報道が個人運営DBを引用した同分野の実例は未確認（さくらチェッカー等の隣接例はあり）。
3. **成長ループ内蔵度**: 半内蔵（貼られる恒久URL＋定期ランキング。共有は起きるが構造強制ではない）。
4. **天井**: 転職検討者は常時数百万人おり、月次10^4〜10^5は蓄積後に現実的。データB2B販売は営業を伴う点が制約と干渉。
5. **維持コスト**: クローラー保守＋名寄せ精度管理＋削除要求対応。ソロ可能だが法務対応が発生しうる。
6. **根拠**: 自力でデータが作れる観測所型の中で母数が大きい。減点は網羅性の法的制約と日本語圏での引用実例不足。

## A3. 見積もりのLevels.fyi（工事・修繕明細行台帳）— スコア 4/10
1. **最初の1,000人の経路**: 描き切れない。照合価値はコーパスが要る＝初期投稿者への提供価値が薄い二重コールドスタート。Levels.fyiの初期は「既に年収を共有する文化があるBlind」に乗ったが、日本のリフォーム見積もりに相当する共有文化・たまり場が確認できない。最初の1,000診断を集める面が「見積もり チェック」検索になるが、そこは既に無料競合が占有し始めている。
2. **経路の実在検証**: 弱い。反証が具体的: Kirei Oneが2025年11月から無料のAI見積もり適正診断を提供開始、他にも見積もりチェックAI・リフォなび見積診断・MYリフォームラボ等が2025年に乱立（§0-9）。送客業者は無料診断を客寄せにできるため、集客面で中立台帳が同じクエリを取り合うのは不利。「診断結果の共有が拡散を生む」JP実例は未発見（§0-5）。中立・データ公開の差別化は本物だが、それは製品差であって集客経路ではない。
3. **成長ループ内蔵度**: 半内蔵（共有動機はあるが、見積書は金額・住所等の特定性が高く共有に心理障壁）。
4. **天井**: うまく回れば月10^4〜10^5閲覧だが、初期経路が塞がっているため到達確率が低い。
5. **維持コスト**: 診断精度管理＋業界クレーム対応＋データ検証。ソロ可能。
6. **根拠**: 競合が同じ入口を無料で先取りした事実確認により大幅減点。A4との比較で共有感情・季節フックでも劣る。

## A4. 退去費用の公開台帳（原状回復Levels.fyi）— スコア 6/10
1. **最初の1,000人の経路**: 条件付きで描ける。(1)国民生活センター相談統計・裁判例・ガイドラインで「相場ページ」を自力construction→(2)3〜4月の引越しシーズンに「退去費用実例◯件の分布」を記者・賃貸系YouTuber・X・5ch賃貸スレへ持ち込み→(3)「ぼったくり度診断」を単体で使える無料ツールとして置き、診断者の一部が精算書を投稿。退去費用の告発はX恒常ネタで感情強度が高く、初期100投稿を自分の呼びかけ＋謝礼で集める現実的プランが立つ。
2. **経路の実在検証**: 中。構造化DBの不在は検索で確認（空白は真）。「退去費用ぼったくり」コンテンツの恒常需要も確認（note等多数）。ただし「診断結果共有→拡散」の国内実例は未確認で、Levels.fyi型の再現は文化面が未証明（§0-5）。季節報道フック（毎年3月の退去トラブル報道）は実在し、一次データ保有者の引用ニーズと噛み合う。
3. **成長ループ内蔵度**: 半内蔵（怒り＋損得の共有動機は27案中最強クラスだが構造強制ではない）。

1. **最初の1,000人の経路**: 半分描ける（間違った半分）。テック系求職者1,000人にプロファイルを発行させること自体はHN/X（自作Portfolio MCPの流行りは事実）で可能。しかし価値が生まれる側=「採用側AIが候補者MCPを照会する」行動が現存しない: 確認できたのはGreenhouse MCP（2026-05-07）・Workable MCP（2026-05-13）で、いずれも採用担当者が自社ATSデータをAIから触るための内向きMCP（§0-9）。外部の候補者エンドポイントを叩く採用エージェントの実例は確認できず。照会が無ければ登録者は幽霊プロファイルを持つだけで、リテンションもループも起動しない。

4. **天井**: 照会行動が生まれれば大きいが、それは他社（ATS・採用ツール側）の意思決定に完全依存。自力で天井を上げられない。
5. **維持コスト**: 低い。
6. **根拠**: 「作れるし配れるが、届いた先で何も起きない」タイプ。時流の先取りとしては最速級だが、集客現実性の評価軸では投機。
